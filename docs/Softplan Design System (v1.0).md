# Softplan Design System (v0.1)

本规范定义了 **Softplan (Software Effort & Cost Planning System)** 的视觉语言与交互逻辑。作为一款开源的分析平台，我们的设计目标是：**严谨、高效、透明**。

------

## 1. 设计哲学 (Design Philosophy)

Softplan 的设计基于以下三个核心原则：

- **精密感 (Precision):** 估算是一门科学。界面应减少装饰性元素，确保数据和逻辑是核心。
- **流转感 (Flow):** 自动化流程应通过色彩过渡（如渐变）引导用户视线，体现数据从“输入”到“结论”的流动。
- **透明度 (Transparency):** 每一个估算结果都必须是可解释的。视觉上通过清晰的层级区分“系统自动计算”与“人工手动修正”。

------

## 2. 色彩系统 (Color Palette)

我们选择 **Indigo (靛蓝偏紫)** 作为品牌色，象征深度分析与技术可信度。

### 核心色板

| **类别**                | **变量名**       | **代码 (Hex)** | **用途描述**                         |
| ----------------------- | ---------------- | -------------- | ------------------------------------ |
| **主色 (Primary)**      | `--sp-primary`   | `#5850EC`      | 核心操作、品牌标识、主导航。         |
| **自动化辅助 (Accent)** | `--sp-accent`    | `#06B6D4`      | 自动化计算标识、数据流向、高亮结论。 |
| **背景 (Surface)**      | `--sp-bg-main`   | `#F8FAFC`      | 全局背景，采用冷灰色调减少视觉疲劳。 |
| **容器 (Card)**         | `--sp-bg-card`   | `#FFFFFF`      | 分析模块、表单容器。                 |
| **文字 (Primary Text)** | `--sp-text-main` | `#111827`      | 标题、核心数值、重要说明。           |

### 语义色彩 (Semantic Colors)

- **成功 (Success):** `#10B981` — 估算完成，逻辑校验通过。
- **人工介入 (Intervention):** `#F59E0B` — **核心！** 用于标记经过人工修正的因子或手动输入的数值。
- **错误 (Error):** `#EF4444` — 逻辑冲突、数据缺失或估算溢出。

------

## 3. 视觉规范实践 (Implementation Guide)

### A. 自动化的视觉传达 (Automation)

当系统执行高自动化任务（如蒙特卡洛模拟、工作量预测）时，应使用以下渐变效果：

- **背景渐变:** `linear-gradient(135deg, var(--sp-primary) 0%, var(--sp-accent) 100%)`
- **动效:** 进度条应具有从左至右的呼吸感，暗示数据正在处理。

### B. 可解释性布局 (Explainability)

为了让复杂的估算模型易于理解，遵循以下 UI 规则：

1. **卡片封装:** 每个分析模型（如 COCOMO II, FP Analysis）必须封装在带 1px 边框的独立卡片内。
2. **脚注系统:** 关键算法输出旁需带有一个微小的 `Info` 图标，悬浮显示该数值的计算公式。
3. **对比度:** 正文文字对比度必须满足 **WCAG AA (4.5:1)** 标准，确保专业报表的可读性。

### C. 人工介入标识 (Manual Override)

这是 Softplan 的特色。当用户修改了系统推荐值：

- **输入框反馈:** 边框色由 `--sp-primary` 变为 `--sp-intervention` (琥珀色)。
- **状态标签:** 在数值旁显示一个小的 `[Edited]` 标签。

------

## 4. 间距与排版 (Typography & Spacing)

- **字体:** * **西文:** `Inter`, `system-ui`, sans-serif (Inter 字体在处理数据表时具有极佳的等宽感)。
  - **等宽:** `JetBrains Mono` (用于展示估算公式或导出 JSON 配置文件)。
- **间距单位:** 基础单位为 `4px`。
  - 模块间距: `24px (6rem)`
  - 组件内间距: `12px` 或 `16px`

------

## 5. 开发者规范 (For Contributors)

1. **禁止直接写死 Hex:** 严禁在 CSS 中直接使用 `#5850EC`，必须引用变量 `var(--sp-primary)`。
2. **组件复用:** 在新增分析模块前，请先查阅 `src/components/ui` 是否已有封装好的 `EstimationCard` 或 `DataGrid`。
3. **暗黑模式适应:** 所有的颜色变量需在 `:root[data-theme='dark']` 下有对应的深色映射。
